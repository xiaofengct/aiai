## 怎么装

1. 打开 [Releases](../../releases)，下载最新一版的 `aiai-<版本>-arm64-v8a.apk`
2. 传到手机点开安装（提示「未知来源」就允许）
3. 如果提示**签名不一致** ⇒ 手机上装的那个不是用同一把钥匙签的，必须卸载重装（数据会没，先导出）

系统要求：**Android 7.0（API 24）及以上**。

★ 装完之后怎么配模型、怎么导入角色卡、怎么聊天 —— 全在 [**使用说明**](USAGE.md)，配真机截图。

### 只提供 arm64-v8a 一个包

| 架构 | 覆盖设备 | 本仓库是否提供 |
|---|---|---|
| `arm64-v8a` | 2018 年后的绝大多数安卓手机 | ✅ |
| `armeabi-v7a` | 很老的 32 位手机 | ❌ 不提供 |
| `x86_64` | **安卓模拟器** | ❌ 不提供 |

★ 刻意不提供 `x86_64`：模拟器带调试器、可 root、快照随便回滚，是逆向工程最省事的入口。
不在这三类里的设备点「检查更新」会如实显示「**这个版本没有适合你这台手机的安装包。**」——
**不会**装错包，也**不会**谎报「已是最新版本」。

## ⚠️ 关于国内网络（重要）

更新源用的是 `raw.githubusercontent.com`，这个域名在国内**经常解析不了**。
表现：App 点「检查更新」提示「连不上更新源」。

- **不影响已经装好的 App 正常使用** —— App 本身不依赖这个域名，只有「检查更新」这一个按钮会碰它。
- 想让它能用：挂代理；或者直接来 [Releases](../../releases) 手动下新包自己装。
- 网络失败时 App 会**如实说连不上**，**不会**谎报「已是最新版本」。

## 更新是怎么工作的

```
App 点「检查更新」
  → GET update/version.json（本仓库 main 分支）
  → 只比 versionCode 整数（不比字符串版本号）
  → 有新版 ⇒ 从 Releases 下载对应 ABI 的 APK
  → 先核对 sizeBytes 与 sha256，对不上就直接删掉
  → 交给系统安装器，由你亲手点「安装」
```

- **不自动检查、不自动下载、不后台偷跑**，每次都由你点。
- 下载只认 `sizeBytes` + `sha256`，任一不符 ⇒ 丢弃并提示。
- 选包只看本机真实 ABI，**不会「找不到就随便装一个」**。
